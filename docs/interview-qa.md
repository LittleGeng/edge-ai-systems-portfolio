### Q01 [基础] 为什么选择 EdgeDiffusion 和 SmolVLA，而不是再做一个通用大模型微调项目？

## EdgeDiffusion

### Q07 [基础] EdgeDiffusion 项目的最小可用基线是什么？

**60 秒短答：** 最小基线必须能加载固定数据、完成短训、保存并重载 checkpoint，再用统一 harness 跑确定性评测。只有这条链路通过，后续编译和加速结果才有可信参照。

**深入答案：**

基线固定代码 commit、数据版本、shape、seed、精度、warmup 和计时边界。冷启动、训练、推理和闭环评测分开记录，防止把环境安装成功误写成模型实验成功。

### Q08 [基础] 为什么选择 PushT 或相近的小型任务做 smoke test？

**60 秒短答：** 它的训练和评测成本低，能快速验证数据、模型、环境和闭环接口，同时保留视觉或状态到动作的序列建模特征。它适合作为工程门禁，但不代表最终泛化结论。

**深入答案：**

### Q09 [进阶] 如何定义 EdgeDiffusion 短训是否通过？

**60 秒短答：** 通过条件不是进程退出码为零，而是 loss 有限、完成预设 step、checkpoint 存在且可重载、固定输入输出 shape 正确，并且最小 rollout 不触发接口异常。

### Q10 [进阶] 怎样测量 diffusion policy 的推理延迟？

**60 秒短答：** 区分首次调用与稳态，固定 observation horizon、action horizon、推理步数和 batch。GPU 计时使用同步或 CUDA event，报告 P50/P95、吞吐、显存和完整策略调用的端到端时间。

**深入答案：**

### Q11 [高级] 如何决定 EdgeDiffusion 应优先优化训练还是推理？

## 编译与性能

### Q13 [基础] torch.compile、TensorRT 和 Triton 各自适合什么问题？

**60 秒短答：** torch.compile 先解决 Python 和图融合开销，TensorRT 面向约束明确的部署图和低精度优化，Triton 只针对 profiler 证明的高价值热点。选择依据是端到端收益，不是工具数量。

**深入答案：**

一般从 eager 基线开始，依次评估 compile 和 TensorRT；只有现有后端无法生成有效 kernel，且热点占比足够高时才写 Triton。每条路径都经过相同正确性与任务级回归。

**深入追问：**

- **为什么不直接写 CUDA？** 开发和维护成本更高，除非 Triton 表达不了且热点收益足以覆盖成本。

- **三者能组合吗？** 可以，但边界会增加编译、搬运和调试复杂度，必须用 trace 证明组合后端有端到端收益。

### Q14 [基础] 什么是 graph break，为什么会影响性能？

**60 秒短答：** graph break 是编译器无法继续捕获图而回到 Python/eager 的边界。它会减少融合、增加 launch 和同步，但少量 break 不一定决定性能，仍要看发生位置和频率。

**深入答案：**

常见原因包括数据依赖控制流、Python side effect、动态 shape 和不支持算子。处理顺序是定位、纯化稳定路径、限定输入契约，再决定局部编译或保留图外逻辑。

**深入追问：**

- **有 graph break 就算失败吗？** 不是。若断点在低频或低占比路径，局部编译仍可能有价值。

- **fullgraph 应该总是开启吗？** 它适合做兼容性门禁，但生产是否启用取决于动态行为和失败回退需求。

### Q16 [进阶] 动态 shape 和 FP16 误差如何处理？

**60 秒短答：** 动态 shape 先按真实流量划分 profile 或 bucket，避免用过宽范围牺牲 tactic；FP16 既做逐层误差，也做最终动作和任务成功率回归，阈值在实验前声明。

**深入答案：**

误差定位要区分正常舍入、累积放大和算子语义差异。对敏感层可保留 FP32，动态维度无法稳定优化时使用分段或明确 fallback，并记录 profile miss。

**深入追问：**

- **最大绝对误差够吗？** 不够，还需相对误差、分布统计、NaN/Inf 和任务级变化。

### Q52 [进阶] 为什么“已经切到 SSH”会成为严重的工程错误？

**60 秒短答：** 配置公钥和本地别名不等于真实连接成功。没有 HostName/Port 和一次端到端探针，就不能宣称切到 SSH；错误陈述会让后续自动化建立在不存在的控制通道上。

**深入答案：**

修复不只是改措辞，还要定义完成条件：端点已保存、key-only 连接成功、远端 hostname 匹配、并发探针返回且浏览器关闭不影响任务。监控在端点缺失时显式显示不可实时监控。

**深入追问：**

- **Jupyter 终端能否替代？** 可作紧急核验，但依赖浏览器会话，不适合可靠轮询和长期部署。

- **如何验证浏览器关闭后仍运行？** 任务用脱离会话的 worker，SSH 重连读取同一 PID、状态和日志。


**回答中的数字模板：** SSH 完成门禁 [待实验填写] 项，端点验证节点 [待实验填写]。

### Q53 [高级] 固定写入 1% 进度为什么有害，怎样重新设计？

## 系统设计

### Q55 [基础] 本地监控系统的控制面和数据面分别是什么？

**60 秒短答：** 控制面维护资源、任务、预算和调度状态；数据面是远端训练、推理和 artifact 流。监控 API 只读发布事实，避免页面操作直接改变远端资源。

**深入答案：**

SSH 探针和平台查询属于采集适配器，reconciler 合并状态，事件日志保留变更。训练进程不依赖浏览器，控制面故障不应终止数据面工作。

**深入追问：**

- **为什么本地运行控制面？** 单用户阶段便于保管凭据和证据；规模扩大可迁移服务端而保持接口。

- **控制面挂了怎么办？** 远端 worker 继续，恢复后从状态文件和平台事实重建。


**回答中的数字模板：** 控制面恢复时间 [待实验填写] s，数据面中断 [待实验填写]。

**应出示的证据：** `scripts/reconcile_loop.py`、`scripts/task_runner.py`、`config/guardrails.json`

### Q56 [基础] 什么是幂等任务，为什么云实验需要它？

**60 秒短答：** 同一任务重复下发不会破坏有效结果或产生不可区分的重复产物。云端断线和重试常见，幂等能让恢复安全。

**深入答案：**

输入、配置和代码形成任务 key，每次尝试有独立 run ID；输出先写临时目录，通过后置条件后原子发布。发现已完成 artifact 时验证哈希再跳过。

**深入追问：**

- **训练本身能完全幂等吗？** 数值执行未必位级一致，但提交与 artifact 管理可以幂等，并明确随机性。

- **如何处理两个 worker 竞争？** 使用 lease/锁和唯一提交键，失败 worker 的临时结果不发布。


**回答中的数字模板：** 重复调度 [待实验填写] 次，重复 artifact [待实验填写] 个。

### Q57 [进阶] 实验 artifact 仓库应该如何组织？

**60 秒短答：** 按项目、任务、run ID 和 artifact 类型组织，manifest 是入口，原始数据不可变，汇总表由脚本生成。大模型、数据和 trace 使用内容哈希与保留策略。

**深入答案：**

- **什么时候删除失败日志？** 按敏感性和存储预算设期限；关键故障最小复现与摘要长期保留。

### Q58 [进阶] 需要哪些可观测性信号才能解释一次实验？

**60 秒短答：** 至少有结构化状态、事件、日志、指标和 trace。状态回答现在在哪，事件回答如何变化，日志解释上下文，指标看趋势，trace 定位时序和瓶颈。

**深入答案：**

所有信号共享 run ID、node ID 和单调时间；采集失败本身也是状态。高频指标采样，关键转换立即记录，避免把所有信息塞进一份无结构大日志。

**深入追问：**

- **日志和事件有什么区别？** 事件是稳定 schema 的关键状态转换，日志是更丰富但不稳定的诊断上下文。

- **如何控制存储？** 指标降采样、日志分级、trace 按故障或抽样保留，证据引用防止误删。


**回答中的数字模板：** 事件延迟 [待实验填写] s，trace 保留率 [待实验填写]%。

### Q59 [高级] 多节点自动化如何保护密钥和远端权限？

**60 秒短答：** 使用专用 key、key-only SSH、最小权限和本地受限配置；不把密码、token 或私钥写入仓库、日志和 manifest。远端命令固定模板并校验节点。

**深入答案：**

控制与采集分角色更安全：只读监控 key 不能创建或删除实例，部署权限单独审计。host key、连接目标和命令参数都要验证，敏感输出在进入事件前脱敏。

**深入追问：**

- **root 登录是否合理？** AutoDL 容器常默认 root，但仍应通过受限 key、固定入口和最小外部权限降低风险。

- **如何轮换 key？** 先部署新公钥并验证，再撤销旧 key；配置引用 key 路径而不复制私钥。
